### Page r2, 08.10.2026 (Claude, on Gev's requirement)

- **One design source.** The page loads `tokens.css`, which is `design/tokens/kryuk.tokens.css` byte for byte; `style.css` holds no colour value of its own. Answers are picked first and saved by «Сохранить ответы»; each question shows its own result, a partial failure is never shown as success and the choice is kept (also across a reload in the same tab). A second tap or a retry repeats the same request key, and the same photo bytes are stored once.
- **Phone layout:** smaller headings and spacing, 48 px buttons. Checked in Chromium at 360, 390 and 430 px, light and dark, with `deploy/browser_check.py` (112 checks, a local portal with sample data behind a throwaway certificate; not the server, not a phone).
- Tests: 28 (the design files are public, the page script and the data are not; rows marked as a test are out of every state and preview; the test account; the outbox; the hand-over as a checked hard link, never a silent copy; a test answer never reported as Armen's).

### Implemented

- Separate backend login (`armen`) through the portal's own Russian login form, optional separate `gev` review credential. Since session fix r1 (08.10.2026) the password is checked once, at login; after that an 8-hour session cookie carries the identity, and a Basic `Authorization` header alone grants nothing. Username/role is determined by the verified credential at login, never by a later request body. Gev review account is read-only in this portal. Armen cannot call owner approval/payment/publication routes; those routes are not implemented and existing backend credentials remain separate.
- Password provisioning is interactive with getpass, salted PBKDF2-HMAC-SHA256 600,000 iterations; plaintext/password hash never embedded in HTML or output. Requires actual HTTPS reverse proxy; loopback test does not validate deployed HTTPS.
- Phone-first Russian UI: gallery multiple selection, camera capture, purpose selection, sequential uploads with individual failures and acknowledgement. Accepts JPEG/PNG/WebP up to 20 MiB/file, single-frame 40 MP maximum. HEIC/video unsupported with visible guidance. Data quota 1 GiB includes private files/orphans; no automatic deletion. Decoder verifies/loads images, bounded upload concurrency; originals preserved byte-for-byte, separate JPEG previews have no supplied EXIF metadata. Original GPS/plates are retained privately; NO masking/publication approval is implied.
- Five one-tap questions: availability now; inquiries today; completed trips today (0/1/2/3/4/5+ or unknown); current service area; main inquiry source. Date is server-selected Moscow date; unknown option on every question. Answer changes append history; network retry uses same key. These are ARMEN_REPORTED statements, not paid orders, verified completions, revenue or profit. No accounting/order row is created and no existing operator task is auto-completed.
- Separate SQLite and media store, outside all existing runtime data/code. Daily view and last 100 photo previews. Browser CSRF header + exact HTTPS Origin on writes; no cross-origin response grants. No iframe embedding, no cache, no external fonts/scripts/analytics. Password brute force: per-process shared failed-auth cap plus required Nginx per-IP rate limit. Session (fix r1): a random 256-bit token in a host-only `__Secure-kryuk_armen` cookie (Secure, HttpOnly, SameSite=Strict, path of the portal, 8 hours, no sliding renewal); the server keeps only its SHA-256 digest, in memory, with the actor, a per-session CSRF token and the deadline. «Выйти» revokes that session; a new login revokes the session presented with it; other devices stay signed in until their own expiry. A restart ends every session; a credential change needs a restart, as before. At most 1024 sessions and two password checks at a time.

### Verification

21 tests PASS on Windows (Claude, Python 3.12.10, Pillow 12.3.0, 08.10.2026); the first 13 also on Linux at GPT's. Third review fixes of 08.10.2026, found and reproduced by GPT: (a) the page state read the day more than once, so midnight inside one request could give the new day with the previous day's answers; the day is now read once for the whole answer. (b) the login body limit of 8192 bytes did not cover every allowed password: 1024 emoji sent as escaped JSON are 12 bytes a character (12325 bytes with the name) and got 400, while the same password as UTF-8 got 200; the limit is now 16384 bytes, above the largest body the rules allow (1024 and 64 such characters, about 13.1 KiB). One test for each; both fail on the code before the fix. The 19 before them: Second review fixes of 08.10.2026, found by GPT: (1) two uploads of the largest allowed size at once took more memory than the unit allows (measured here on Windows before the fix: 860 to 939 MiB peak for two 40 MP pictures, `MemoryMax` is 768M); now one picture is decoded at a time and it is made small before it is turned and converted, so the full-size picture is in memory once (measured after: 346 MiB for two 40 MP RGBA PNG, 187 MiB RGB PNG, 42 MiB JPEG); a test measures the peak of a separate process and fails above 512 MiB. Not measured on the VPS, and not through the HTTP server, which also holds the two request bodies (up to 20 MiB each). (2) the repeat of an already saved answer with the same key was refused after midnight, because the date was checked before the key; now the saved result is returned, and only a new answer must carry today's date. (3) answers and photos are listed in the order they were saved (SQLite `rowid`), not by time text and random id, so with equal times the last saved answer is the one shown. Four tests: one for each, and one for the preview (orientation, palette and other modes, a cut file refused); the first three fail on the code before the fix. Review fixes of 08.10.2026, found by GPT: login checks the name and password directly (wrapped as a Basic header, a long non-ASCII password that provisioning accepts passed the 2048-byte limit and was refused; the login body limit is 8192 bytes for the same reason); a malformed `X-CSRF-Token` header is refused with 403 (it used to raise inside the comparison and close the connection); when a session has ended the page goes back to the login form with «Время входа истекло. Session-ի ուղղում r1 (08.10.2026). գաղտնաբառը ստուգվում է միայն մուտքի պահին, հետո 8 ժամ գործում է session cookie-ն, կա «Ելք»։ 15 թեստն անցել է Windows-ում (Claude), դրանցից առաջին 13-ը նաև Linux-ում (GPT). JS syntax-ն էլ ստուգված է։ GPT-ի review-ի ուղղումները (08.10.2026). մուտքը անունն ու գաղտնաբառը ստուգում է ուղիղ (երկար ոչ լատինատառ գաղտնաբառը առաջ մերժվում էր). սխալ CSRF header-ը մերժվում է 403-ով, ոչ թե կապը կտրվում. session-ի ավարտից հետո էջը վերադառնում է մուտքի ձևին՝ «Время входа истекло. Войдите снова.» հաղորդագրությամբ։ Իրական հեռախոսի, browser visual-ի, Nginx/VPS տեղադրման ստուգում դեռ չկա։ GPT-ն սերվերի մուտք չունի և Արմենի իրական հաշիվ/գաղտնաբառ չի ստեղծել. փաթեթը պատրաստ է Քլոդի համար։

Քլոդը առանձին PR-ով ինտեգրում է, CI-ով ստուգում, իրական Nginx-ը նախ կարդում, առանձին համակարգային օգտատեր/բազա/նկարների պանակ ստեղծում։ Գաղտնաբառը մուտքագրվում է trusted terminal-ում, ոչ չատում կամ կոդի մեջ։ Պահպանվում են Գևի/Bro-ի մուտքի սահմանները։ Մեկ հսկվող start է, autostart/timer առանձին թույլտվությամբ։ Հետո փաստացի հեռախոսային ստուգում և հաստատված հասցե։ Գործող runtime-ի բազային, ops_views.py-ին ու հաստատված report-ին փոփոխություն չկա։ Նոր տվյալների backup/restore-ն պետք է ստուգել մինչև իրական աշխատանքի վրա հենվելը։
