# KRYUK24: operations

Install, backup, recovery and rollback. Only commands and procedures that exist in the project's sources are written here, and each says whether it was **actually executed** and **verified**. Where the sources hold no procedure, this file says so instead of inventing one.

`<VPS>` stands for the server address; it is in the private notes. No secret value appears here. Server commands are run over SSH as the user `kryuk` (key login only), with `sudo`.

Standing limits for every procedure: the runtime stays in STAGING with `sending_enabled: false`; no timer or autostart is created for Bro or for the API reader; `ops_views.py` (sha256 `f5f6e9d8…`) is never overwritten and never put into a patch; nothing is published, paid or sent without Gev's separate yes.

## 2. Site

Source: `site/README.md`. The site is static files in the hosting account's `kryuk24/public_html`. There is no FTP; upload goes through the hosting file manager.

Deploy:

1. Raise `?v=` for a changed `styles.css` or `app.js` in `index.html` (and `VER` in the generator if SEO pages changed): the hosting caches CSS and JS for 7 days. City and service pages are generated by `tools/make_seo_pages.py` and are not edited by hand.
2. Check locally: `tools/.venv/Scripts/python.exe tools/tests/run_checks.py`. Expected: issues 0, errors [], links_bad [].
3. Show Gev and get his yes.
4. Put the changed files into a zip with paths from the site root, upload it through the file manager into `kryuk24/public_html`, and unpack it there. Claude Code's automatic mode refuses this upload and unpacking; Gev switches to manual approval and confirms the request.
5. Move the zip out of `public_html` into the account's home folder, so that it cannot be opened by a link.
6. Compare the hashes of the live files with the local ones and run `run_checks.py live`.
7. `git commit`, `main` on that commit, `git tag vNN-live`, record it in [`CURRENT_STATE.md`](CURRENT_STATE.md).

Executed and verified: last deploy `v33.1-live`, 06.10.2026 (57 of 58 hashes equal; `.htaccess` cannot be read from outside).

Rollback of one file. The earlier README gave `git checkout v32-live -- 06_Landing/index.html`: in the old history the site folder is `06_Landing/`. The file must then be deployed again by the steps above. Not recorded as executed. After the clean import to GitHub the old tags exist only in the git bundle.

Local preview: `python -m http.server 8765` from the site folder. Executed before (stopped on 07.10.2026; the port is free).

## 4. API reader: rollback

Source: the same README, section "Rollback". **Not executed on the real server.** What was executed: `rollback` on a temp copy of `/opt/kryuk24` returned the four original sha256 (v0.3.0, the four patched files are byte for byte the same in v0.3.2); a test kills a real `apply` process in the middle and `rollback` gives back every byte.

1. `sudo systemctl stop kryuk-operations.timer`; wait for a run in progress as in install step 5; `sudo systemctl stop kryuk-capture kryuk-bro-api`.
2. `sudo python3 install_patch.py --code /opt/kryuk24 rollback` until it says `ROLLED BACK`.
3. Database folder and file back to the owner, group and mode recorded in `facts-before.txt` (`chgrp`, `chmod`).
4. `sudo systemctl start` the units that were active before; the read checks of install step 8.
5. `sudo rm -f /etc/systemd/system/kryuk-api-read.service && sudo systemctl daemon-reload`; `sudo rm -r /etc/kryuk24-api-read`; `sudo gpasswd -d kryuk-run kryuk-db`; `sudo userdel kryuk-api-read`; `sudo groupdel kryuk-db`. Restart the services once more after `gpasswd`, so that `kryuk-run` loses the group.

Rows already planned as `API_READ` keep that kind; after a rollback the browser worker can claim them again by job name; observations already written stay.

1. Փոխված `styles.css`-ի կամ `app.js`-ի համար `index.html`-ում բարձրացնել `?v=`-ը (ու գեներատորում `VER`-ը, եթե SEO էջեր են փոխվել). հոստինգը CSS-ն ու JS-ը 7 օր cache ա անում։ Քաղաքների ու ծառայությունների էջերը գեներացնում ա `tools/make_seo_pages.py`-ն, ձեռքով չեն ուղղվում։
2. Ստուգել տեղում. `tools/.venv/Scripts/python.exe tools/tests/run_checks.py`։ Սպասվում ա՝ issues 0, errors [], links_bad []։
3. Ցույց տալ Գևին ու ստանալ «հա»։
4. Փոխված ֆայլերը դնել zip-ի մեջ՝ կայքի արմատից ճանապարհներով, վերբեռնել ֆայլերի մենեջերով `kryuk24/public_html`, էնտեղ բացել։ Claude Code-ի ավտոմատ ռեժիմը էս վերբեռնումն ու բացելը մերժում ա. Գևը դնում ա ձեռքով հաստատման ռեժիմ ու հաստատում հարցումը։
5. Zip-ը հանել `public_html`-ից հաշվի տնային թղթապանակ, որ հղումով չբացվի։

7. `git commit`, `main`-ը էդ commit-ին, `git tag vNN-live`, գրել [`CURRENT_STATE.md`](CURRENT_STATE.md)-ում։

## 4. API reader. հետ գնալը

Աղբյուրը՝ նույն README-ի «Rollback» բաժինը։ **Իրական սերվերում արված չի։** Ինչ արվել ա. `rollback`-ը `/opt/kryuk24`-ի ժամանակավոր պատճենի վրա վերադարձրել ա չորս սկզբնական sha256-ը (v0.3.0-ով. patch-ի չորս ֆայլը v0.3.2-ում բայթ առ բայթ նույնն են). թեստը սպանում ա իրական `apply` պրոցեսը մեջտեղում, ու `rollback`-ը վերադարձնում ա ամեն բայթ։

1. Կանգնեցնել `kryuk-operations.timer`-ը, սպասել ընթացիկ run-ին, կանգնեցնել `kryuk-capture`-ն ու `kryuk-bro-api`-ն։
2. `install_patch.py --code /opt/kryuk24 rollback`, մինչև ասի `ROLLED BACK`։
3. Բազայի թղթապանակն ու ֆայլը հետ բերել `facts-before.txt`-ում գրված տիրոջը, խմբին ու mode-ին։
4. Միացնել էն unit-ները, որ միացած էին. install-ի 8-րդ քայլի կարդացող ստուգումները։
5. Ջնջել unit ֆայլը ու `daemon-reload`. ջնջել `/etc/kryuk24-api-read`-ը. `kryuk-run`-ին հանել `kryuk-db` խմբից. ջնջել `kryuk-api-read` օգտատիրոջն ու `kryuk-db` խումբը։ Խմբից հանելուց հետո ծառայությունները մի անգամ էլ վերամեկնարկել։

Արդեն `API_READ` պլանավորված տողերը պահում են էդ տեսակը. rollback-ից հետո զննարկչի աշխատողը նորից կարա վերցնի դրանք գործի անունով. գրված դիտարկումները մնում են։

## 9. Փորձեր (Windows)

Աղբյուրը՝ `runtime/wip/trial/TRIAL_PLAN.md`։ Իրական run-ը ծախսում ա բաժանորդագրությունը ու ուզում ա Գևի «հա»-ն ճիշտ մեկ run-ի համար։

| Քայլ | Հրաման | Արվե՞լ ա |
| --- | --- | --- |
| Միակ մեկնարկը, Գևի ձեռքով, մեկ անգամ | `launch_case.ps1 -Case T1 -RerunReason "<text>" -Execute` (ինքն ա քշում preflight-ն ու Chrome-ի ստուգումը, հետո մեկ run, 240 վրկ սահման, առանց կրկնության) | Հա. T1 attempt-04 ու T2 attempt-01, 07.10.2026 |

Run-ից առաջ. ճիշտ մեկ կպած զննարկիչ (կարդալ զննարկիչների ցուցակը. native host-երի քանակը դրա ապացույցը չի). Chrome-ի մյուս պրոֆիլները, editor-ն ու Claude-ի նիստերը Գևն ա փակում ձեռքով. launcher-ը ոչինչ չի փակում ու չի սպանում։ T2 չկրկնել, T3 չսկսել, մինչև GPT-ն որոշի proxy-ի փաթեթը։
